# Signature composition coverage

This suite links **Ed25519, RSA, MLDSA, Secp256k1, P256, SHA256 and HMAC**
into the same canister. The ordinary integration fixture loads the same seven
plugins in reverse order. It complements each plugin's isolated tests by
checking simultaneous native linking and shared-heap use through `mo:fast`.
The Ash configuration enables `--sanity-checks --force-gc`.

| Ash method | Behavior checked |
| --- | --- |
| `test_independent_answers_with_seven_plugins_linked` | Independent valid signatures for all five signature modules, including secp256k1 ECDSA and BIP340; SHA-256-to-RSA prehash composition and RFC HMAC output. |
| `test_error_paths_do_not_poison_other_plugins` | Interleaved malformed signatures, invalid prehash and secret lengths, changed messages/context, then every original valid answer. Errors in one plugin must not affect later operations in another. |
| `test_hash_mac_and_signature_pipeline` | Prepared and incremental HMAC results feed Ed25519 as message bytes and SHA-256/ECDSA as prehashes; exact HMAC expected bytes, changed-message rejection, retained output integrity, and stream reset. This composition supplements independent signatures rather than replacing their known-answer checks. |
| `test_all_outputs_and_inputs_survive_messages_and_collection` | Dynamically allocated inputs and native key/signature/hash/MAC results remain reachable through persistent actor state, transient state, array aliases and a suspended continuation. Exact independent output bytes survive 13 async boundaries and confirmed reclamation; all five native verifiers consume the retained outputs afterward. |

There is exactly **one RSA signing call and one ML-DSA signing call** across
the actor suite. The collection loop does not repeat these expensive calls.
It allocates 72 MiB of disposable arrays over nine continuations, crossing
the current collector's 64-MiB allocation partition, followed by four settling
continuations. More than 4 MiB of additional `rts_reclaimed()` is required;
awaits or allocations alone are not accepted as evidence of collection.
Comparisons use independent constant bytes as well as the aliases, so jointly
corrupted references cannot pass by agreeing with each other.

## Independent expected answers

- Ed25519: [RFC 8032 section 7.1, test 2](https://www.rfc-editor.org/rfc/rfc8032.html#section-7.1), including its one-byte message, seed, public key and signature.
- P256: [RFC 6979 appendix A.2.5](https://www.rfc-editor.org/rfc/rfc6979.html#appendix-A.2.5), SHA-256 of `sample`, preserving its specified high-s signature.
- Secp256k1 ECDSA: the independently checked fixed answer used by the existing [Secp256k1 suite](Secp256k1.md), secret scalar 1 and SHA-256 of `sample`. BIP340: [official test vector 0](https://github.com/bitcoin/bips/blob/master/bip-0340/test-vectors.csv), secret scalar 3 and zero message/auxiliary input.
- RSA: the package-local [RSA fixture](../../fixtures/RSA.mo), independently generated by Node.js/OpenSSL. Its public test CRT key, message containing NUL, SHA-256 digest, public modulus, signature and recovered salt support an exact signing comparison. These keys are public test data, never production secrets. See [RSA coverage](RSA.md).
- MLDSA: official NIST ACVP ML-DSA-44 deterministic signature-generation **group 1, case 4**, from [commit 975de31eb83d87039ec88934fdc47d8c312b892d](https://github.com/usnistgov/ACVP-Server/blob/975de31eb83d87039ec88934fdc47d8c312b892d/gen-val/json-files/ML-DSA-sigGen-FIPS204-tr1/internalProjection.json). The fixture embeds that case's complete seed, public key, one-byte message, 59-byte context and 2420-byte signature. It has no dependency on source outside the published package. The source JSON SHA-256 is `b61576c765b1eb0e6a667a67a68380df944592be8740f9c020c9ea5a89136f18`.
- HMAC-SHA256: [RFC 4231 test case 1](https://www.rfc-editor.org/rfc/rfc4231.html#section-4.2), twenty `0x0b` key bytes and `Hi There`.

The top-level `tests/integration/run/signature-composition.mo` repeats the
independent vectors with reverse plugin ordering, invalid-then-valid recovery,
and direct signing/hash composition. It does not perform the actor lifetime
test. Both sources carry the same compact NIST case to keep the public package
self-contained.

These are functional assertions, not isolated performance measurements. Ash
metrics for the collection method cover only its final validation block,
excluding signing, allocations and asynchronous phases. Tests do not prove
constant-time behavior, secret erasure, canister upgrade safety, every possible
GC schedule, or cryptographic certification.

Run after building all seven matching plugins:

```sh
scripts/test-ash.sh --ash-source /srv/shared/code/ash SignatureComposition
```

Source review and execution results are tracked in the round's central
validation report. Adding the sources alone is not a claim that they passed.
