# Bitcoin BIP32 composition coverage

The `BitcoinCryptoBip32` suite executes the same assertions as
`tests/run/crypto-bitcoin-bip32.mo`, using
`tests/lib/BitcoinCryptoBip32Cases.mo`.

| Method | Coverage |
| --- | --- |
| `test_official_roundtrips` | All 17 public keys from BIP32 vectors 1–4, exact metadata, master constructor, fingerprint, independently encoded testnet tpub and network preservation |
| `test_official_derivation` | Six official non-hardened parent/child edges, multilevel relative derivation, absolute root paths, exact maximum non-hardened index oracle |
| `test_invalid_official_keys` | All 16 invalid keys from BIP32 vector 5, malformed Base58 and checksummed payloads with seven incorrect lengths |
| `test_path_validation` | Root/relative forms, full non-hardened numeric range, malformed separators, whitespace, signs, suffixes, Unicode digits, overflow and absolute-path depth checks |
| `test_metadata_validation` | Caller-built malformed records, invalid keys/chain codes/fingerprints, master metadata, empty paths, depths 254/255 and path-length overflow |

The official vectors are from
[BIP32](https://github.com/bitcoin/bips/blob/master/bip-0032.mediawiki).
The maximum-index answer was independently calculated using Python integer
affine curve arithmetic and `hashlib`/`hmac`; that oracle reproduced all six
official public-derivation edges before generating the boundary answer.

The input validation and derivation tests passed the source interpreter,
IR interpreter, lowered IR interpreter and compiled Wasm with sanity checks.
All five public Ash methods also passed on PocketIC. Ash metrics include
assertions and setup and do not constitute comparative benchmarks.

The exceptionally rare invalid HMAC-derived scalar/point branch is not
generated by these vectors. The underlying secp256k1 suite separately tests
out-of-range scalars, the point at infinity and the valid zero tweak.
