# Prepared MLDSA coverage

`MLDSAPrepared.mo` has 12 Ash update tests, loading only `ml-dsa` with
`--sanity-checks --force-gc`. It uses the same pinned official NIST ACVP vectors
as [the direct API suite](MLDSA.md); expected answers are not generated by the
prepared implementation.

| Tests | Behavior |
| --- | --- |
| Six `test_official_prepared_*` signing tests | Exact deterministic and explicitly randomized signatures, including one-byte and 8192-byte messages, empty and 255-byte contexts; prepared verification of every answer. |
| `test_official_prepared_verification` | All 15 official valid/invalid pure external-interface verification cases. |
| `test_prepared_invalid_lengths_and_error_precedence` | Invalid seed/public-key preparation, signature lengths, context 256, randomness lengths, documented error precedence and successful reuse after errors. |
| `test_prepared_keys_interleave_and_bind_context_message` | Independent key handles interleave; wrong keys/messages/contexts reject; prepared signatures match direct signing; nonzero randomness changes bytes; empty-message signing verifies. |
| `test_prepared_noncanonical_hints_and_z_return_false` | Oversized hint count, duplicate positions, z norm boundary and all-zero/all-one signatures return `#ok(false)`. |
| `test_prepared_aliases_and_argument_order` | Factory and operation aliases, generic identity, handle arrays, typed function values, exactly-once left-to-right argument evaluation and repeated signing. |
| `test_prepared_handles_in_transient_state_survive_await_gc` | Prepared public and secret keys remain usable in transient actor fields, continuation locals and aliases through 13 awaits, interleaved preparation/signing and more than 4 MiB observed reclamation after 72 MiB disposable allocation. |

`tests/run/crypto-mldsa-prepared.mo` separately covers exact deterministic and
randomized answers, independent key handles, mismatches, malformed signatures,
error precedence and aliases through the interpreter/Wasm test runner.

Prepared handles are local, opaque and nonstable. This positive runtime suite
uses `transient` actor fields; it does not independently prove that shared or
stable handle types are rejected. Those restrictions require compiler negative
tests. The GC test demonstrates handle usability across observed collection; it
does not prove every GC schedule, secret erasure or upgrade persistence. Test
metrics include assertions and setup, so isolated benchmarks should be used for
performance comparisons.

## Validation

On 2026-10-13, the public direct and prepared run fixtures both passed the
Motoko, IR and lowered interpreters plus compiled Wasm. All **12 prepared Ash
methods** and the unchanged **17 direct methods** passed against SDK
`9f6ebeedc` and runtime `104aedb9…`, including the reclamation assertion.

The private source-Ash runner selects that SDK explicitly, preserving the
installed compiler. Its 42 source-file hashes and the complete logs are recorded
in [public validation](../../../../../plugins/ml-dsa/tests/prepared/public-validation.json).
An initial test annotation attempted to assign an intrinsic directly to an
ordinary function type; the corrected test uses an explicit wrapper. No plugin
or SDK correction was required.
