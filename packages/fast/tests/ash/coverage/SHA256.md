# SHA256 test coverage

Public API: `SHA256.digest(Blob) : Blob`. The Ash configuration loads only the
SHA256 native plugin, so it also checks that importing this module does not
require unrelated plugins.

| Ash test | Behavior checked |
| --- | --- |
| `test_nist_known_answers` | Fixed standard answers for empty input, `abc`, and the 56-byte NIST message. |
| `test_binary_padding_and_block_boundaries` | Forty independent fixed answers at lengths 0–65,537, including both sides of 32-byte specialization, 55/56-byte padding, 63/64-byte blocks, subsequent padding/block transitions, and larger buffers. Inputs include all byte values. Checks output length and unchanged input. |
| `test_aliases_and_concrete_callbacks` | Inferred aliases through records, generic identity, arrays, and options; explicitly typed Motoko callback wrappers. |
| `test_argument_and_callee_evaluated_once` | Exactly-once left-to-right callee and argument evaluation. |
| `test_retained_results_and_million_byte_vector` | NIST million-`a` answer, retained digest across large allocations and 256 differently sized repeated calls, repeated determinism. |

The binary vectors use byte `i = (i * 131 + 17) % 256`. Their committed expected
answers were generated independently with Python's `hashlib.sha256`, using
`hashlib.sha256(bytes((i * 131 + 17) % 256 for i in range(length))).digest()`.
Tests do not compute their expected answers with the plugin or a second copied
SHA implementation.

Both large-input tests use update methods, avoiding query instruction limits.
Metrics include input construction and assertions and are correctness-suite
metrics, not isolated SHA256 benchmarks.

Limits: finite known-answer and boundary cases cannot exhaust arbitrary byte
strings. This suite does not simulate instruction-limit interruption, canister
upgrades, or prove GC reclamation; existing native plugin/GC tests cover
separate compiler/runtime integration concerns. Compile-time unsupported-call
checks live in the package's compile-failure suite.
