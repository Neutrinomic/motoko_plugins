Independent deterministic corpus, run separately for each candidate:
  262,144 polymod step cases against baseline and direct generator contribution oracle.
  408,280 encode cases against baseline.
  9,205,900 decode cases against baseline.
  203,706 conversion cases against baseline, including independent bit-index oracle.
  Candidate3 adds 100 empty-input/invalid-width/noncanonical-pad cases: 203,806 total.

Coverage includes:
  Encode HRP/data lengths 0..100, all modes including noncanonical nonzero mode values,
  lower/upper/mixed case, invalid printable/Unicode bytes, out-of-range data, and
  competing invalid inputs. Decode includes every possible byte mutation at every
  position of 240 independently varied valid encodings and their uppercase forms,
  truncations, separator boundaries, combined failures, UTF-8 sequences, random ASCII,
  and arbitrary byte arrays. Conversions cover all 64 width pairs with 0..257-element
  zero/maximum/random inputs, strict/padded behavior, all single-byte values, invalid
  widths, noncanonical true padding flags, selected longer inputs, and 16 MiB bounds.

Checks:
  Exact public error code and successful output equality with baseline.
  Independent bit-index conversion output and error model, avoiding accumulator logic.
  Guard bytes before/after scratch/output remain intact.
  Input buffers remain unchanged.
  All 90 encode/decode scratch bytes are independent of their initial contents.
  Successful 90-byte scratch contents agree entirely with baseline, including tails.
  Failure scratch need not equal baseline: fused encode may write canonicalized HRP
  before later validation fails. Scratch is fully initialized, and the unchanged
  generator discards it on errors, so this difference has no public semantic effect.

Static review:
  The feedback table computes the same XOR combination of generators for all five
  high bits. The explicit index mask preserves the prior function's behavior even for
  arbitrary u32 states outside normal 30-bit polymod state.
  Encode order remains HRP length, HRP empty/printable, combined length, case, data.
  Decode order remains length, printable bytes, case, separator, checksum length,
  alphabet, checksum. Last separator behavior and uppercase normalization agree.
  Each fast conversion group consumes/writes exactly 40 bits; restarting the generic
  accumulator for the remainder preserves bit alignment. Same-width copies write
  exactly the validated length, with fresh disjoint output allocated by the generator.
  The from=8 range-check elision is valid for u8 inputs.
  Length limits make intermediate arithmetic safe; both bounds are checked before
  validation scans or writes. Inputs are immutable and no raw pointers escape a call.
  Encode/decode initialize the entire scratch before any validation path.
  Generator validation ends before allocation; input pointers are reacquired after
  allocation. Allocation follows the SDK no-GC-safepoint contract.
  Candidate2's empty-input early return preserves all validated empty conversions;
  its nibble key is injective on validated widths 1..8.
  Candidate3 returns empty size only AFTER width validation; all valid empty inputs
  produce zero size under either padding mode. Its u32 width casts preserve values
  1..8 exactly. Live accumulator bits are at most (to - 1) + from <= 15, so using
  u32 for the bit count and shift operands does not alter results or create overflow.

A separate read-only reviewer independently examined unsafe copying, bounds, zero-size
pointers, aliasing and allocation lifetimes and found no defects.

Additional execution:
  Candidate2's and candidate3's entire corpora also pass AddressSanitizer with leak
  detection and Rust debug assertions enabled; no diagnostics. Outputs:
  results2-asan.txt and results3-asan.txt.

Harness construction and limits:
  generate.py copies each source implementation into an owned harness module and
  removes only crate-level no_std/feature attributes, no_mangle attributes, and the
  Wasm-only panic handler/test modules. It exposes step through a forwarding function.
  The audit is native x86_64 Rust, not a direct execution of the built Wasm artifact.
  Public Motoko/Wasm/Ash validation and performance measurement belong to the parent.
  Safety conclusions assume callers honor exported unsafe function contracts,
  particularly validated conversion arguments and non-overlapping readable/writable
  buffers. No production sources or candidate files were changed.
