# HMAC-SHA2

Allocation-free HMAC-SHA256 and HMAC-SHA512 with one-shot, reusable-key and
incremental APIs in `mo:fast/HMAC`. Only this plugin needs to be loaded; the
public module does not require the SHA256 or SHA512 plugins.

```motoko
import HMAC "mo:fast/HMAC";
let tag = HMAC.sha512(key, message);
let keyContext = HMAC.prepareSha512(key);
let second = keyContext.digest(otherMessage);
let stream = keyContext.stream();
stream.write(firstChunk);
stream.write(secondChunk);
let combined = stream.sum();
stream.reset();
```

`sum()` is non-consuming. `reset()` restores the original key, including its
precomputed inner/outer hash states. Updates retain a fixed-size managed Blob,
never the complete message or native pointers. Prepared keys and streaming
contexts contain key-equivalent secret material and should be protected like
the original key; garbage collection does not guarantee erasure.

The Rust runtime uses RustCrypto SHA2 compression and hashes long keys once.
State serialization is canonical big-endian, independent of Rust structure
layout. SHA256 contexts contain 32-byte inner/outer chaining states, an 8-byte
total byte count (including the ipad block), and a 64-byte partial block:
136 bytes total. SHA512 uses 64-byte chaining states, a 16-byte count and a
128-byte partial block: 272 bytes total. Unused partial-block bytes are zero.
Counts below one block, beyond the SHA2 bit-length limits, malformed sizes,
and noncanonical tails trap. The representation is private and may change
with the plugin SDK; applications should use the public classes.

The portable OCaml reference shares the existing SHA256 digest and SHA512
reference through source symlinks. The plugin builder packs these copies in
its own namespace, so runtime loading remains independent. Native tests use
RFC4231, an independent HMAC implementation, split/boundary matrices and guarded
unaligned output buffers. Public Motoko run and Ash tests cover the same RFC
vectors, streaming, prepared-key reuse, resets and evaluation order.

## Measured performance

The crypto benchmark suite uses a 32-byte key, independent expected outputs,
three fresh-canister trials, IC instruction counters and total allocation.
Representative measurements with 64-byte messages:

| Operation | Plugin instructions | Bitcoin 0.2.1 instructions | Plugin allocation |
| --- | ---: | ---: | ---: |
| SHA256, key setup included | 26,614 | 160,271 | 56 bytes |
| SHA512, key setup included | 30,219 | 168,729 | 88 bytes |
| SHA256, key setup excluded | 16,572 | 72,916 | 56 bytes |
| SHA512, key setup excluded | 17,023 | 59,322 | 88 bytes |

Prepared keys remove 38% and 44% of native SHA256/SHA512 instruction cost in
these short-message workloads. Their setup is outside the measured region;
the Bitcoin comparator constructs a fresh HMAC before each measured call.
Bitcoin's prepared comparator is one-shot, whereas the plugin's prepared key
can be reused. Output checks occur outside the measured region.

The Bitcoin measurements are recorded in
`benchmarks/crypto/results/hmac-native-initial` and `hmac-prepared-initial`;
the current native measurements are in `round2-hmac-directout`. Two SHA256 compressor experiments were measured and
rejected: unrolling improved instructions by 2.4–3.2% while adding 8.3 KB to
the runtime; forced inlining improved them by 3–6% while adding 138 KB.
The implementation retains RustCrypto compression and the reusable-key API.

The second optimization round keeps the RustCrypto compression functions and
improves key-pad setup, canonical-state validation/copying, complete-block
batching, and direct serialization into the fresh output Blob. All 32 measured
cases improved across three exact trials, including empty inputs, long keys,
prepared keys and 1/63/128-byte streaming chunks. For 1024-byte messages written
one byte at a time, SHA256/SHA512 instructions fell from 2,503,022/5,210,815 to
1,544,214/3,168,562 (38.31%/39.19%). Allocation is unchanged. The runtime grew
from 36,836 to 38,393 bytes; no cryptographic compressor was replaced.

The baseline, intermediate variants and selected result remain under
`benchmarks/crypto/results/round2-hmac-*`. Workloads and independent Python
oracles are generated by `benchmarks/crypto/round2/hmac-workloads/generate.py`.
