# RSA-PSS

`mo:fast/RSA` signs and verifies RSA-PSS with one explicit interoperable profile:
3072-bit modulus, public exponent 65537, SHA256, MGF1-SHA256, and 32-byte salt.
Public keys and signatures are 384 bytes. Private component blobs are 960 bytes.
Load only the `rsa` plugin to import this module.

```motoko
import RSA "mo:fast/RSA";
let signed = RSA.sign(privateKey, message, salt); // salt is a 32-byte Blob
let valid = RSA.verify(publicKey, message, signature);
```

`signPrehash` and `verifyPrehash` accept exactly 32-byte SHA256 digests instead of
hashing the message. `derivePublicKey`, `validatePrivateKey`, and
`validatePublicKey` provide key operations. All operations return `#ok` or a
specific typed `#err`. Well-formed signatures with incorrect padding or messages
return `#ok(false)`; wrong signature length or a signature integer at least the
modulus returns `#err(#invalidSignature)`.

## Keys and randomness

Generate keys using established external tooling:

```sh
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 \
  -pkeyopt rsa_keygen_pubexp:65537 -out private.pem
openssl pkey -in private.pem -pubout -out public.pem
python3 plugins/rsa/tools/import_key.py --private-key private.pem \
  --private-out secret.rsa --public-out public.rsa
# Or import a public key alone:
python3 plugins/rsa/tools/import_key.py --public-key public.pem \
  --public-out verifier.rsa
```

The converter accepts OpenSSL-readable PEM/DER `rsaEncryption` keys,
rejects restricted RSASSA-PSS key types rather than discarding their policy,
validates private primes and consistency with `openssl pkey -check`, and writes new files with mode 0600.
It does not print secrets. Its fixed output encodings are:

- Public: the unsigned big-endian 3072-bit modulus, 384 bytes; exponent is implicit.
- Private: `p || q || dp || dq || qInv`, each unsigned big-endian 192 bytes.
  `dp = d mod(p-1)`, `dq = d mod(q-1)`, `qInv = q^-1 mod p`.
  Both factors must have 1536 bits and their product must have 3072 bits.

The runtime checks component ranges and CRT inverse relationships on every
private operation. **These are consistency checks, not primality testing or a
proof of key strength.** Import keys generated by established RSA tooling.
The plugin provides no synchronous on-chain prime search: its runtime would be
unbounded and unsuitable for an individual IC message. No private key or native
pointer is retained by the plugin.

Signing requires caller-supplied 32-byte salt. Obtain fresh cryptographic randomness
outside the synchronous plugin, for example through the application's IC randomness
flow. A given key, message, and salt produce exactly the same signature; salt is
public in RSA-PSS and is not a secret signing key. No implicit RNG or state exists.
The constant-time private kernel does not use blinding randomness.

## Implementation and security scope

The native kernel pins BearSSL revision
`7bea48e5e850ab4cafbe68d3765cdaba13a86d6f` and its portable constant-time i31
RSA arithmetic. Secret exponentiation uses fixed-size input components. Signing
checks the completed signature with the public exponent before releasing it,
preventing faulty CRT results from escaping. Private multiprecision workspaces
are explicitly cleared. Caller-owned managed key blobs remain the caller's data;
zeroizing scratch does not erase those blobs or every possible compiler spill.

The fixed PSS/MGF1 layer uses direct BearSSL SHA256 calls. The small documented
[upstream adaptations](runtime/vendor/bearssl/LOCAL_CHANGES.md) remove unused
hash vtable initialization and clear private workspaces. They permit static
Wasm linking without startup functions; no compiler/SDK change is needed.
All scratch is bounded native stack memory, with no global allocator or mutable
state. Private-key bytes and all other input blobs remain unmodified.

Portable OCaml interpreter semantics match native outputs, including explicit
salt, but use variable-time reference arithmetic. Use the compiled Wasm plugin
for private operations requiring the constant-time kernel.

RSA is not post-quantum secure. This module implements signatures only, not
RSA encryption or PKCS#1 v1.5 padding.

## Build and validation

In the matching Motoko Nix shell, build with clang capable of Wasm64:

```sh
scripts/build.sh --motoko /path/to/motoko rsa
cargo test --release --package motoko-compute-rsa
```

The build automatically selects the original compiler behind a Nix clang
wrapper, avoiding host-only flags. `RSA_CLANG` and `RSA_AR` can override the
compiler and archiver explicitly.
The plugin-local build uses freestanding C99, `-O3`, PIC, function/data sections,
and fixed RSA size bounds. It links no libc or external C runtime. Source hashes
include every vendored C/header file and build script; dependency provenance and
original upstream hashes are in `runtime/vendor/bearssl/UPSTREAM.json`.

Tests include independent OpenSSL exact signatures, all public Motoko functions,
malformed keys/digests/salts/signatures, input immutability and managed GC roots.
The separate audit corpus adds pinned Wycheproof PSS vectors and independently
constructed malformed PSS encodings. Benchmark cases record signing, verification,
key derivation and validation separately; message and prehash costs are distinct.
