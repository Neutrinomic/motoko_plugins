# Ed25519 fixtures and measurements

`fixtures/rfc8032.json` preserves all five pure-Ed25519 RFC8032 §7.1 vectors,
with the source URL and downloaded source hash. `generate-fixtures.mjs` creates
`fixtures/openssl.json` with independent Node/OpenSSL key derivation and signing.
These are public test seeds, never application secrets.

`generate-benchmarks.py` uses `../common.py` to emit 14 actors: key derivation,
seeded keypair, validation, sign/verify at 0/32/1024 bytes, wrong messages at each
length, well-formed wrong signature and malformed signature. The timed region
contains one public module call and assigning its result. Input setup, independent
exact-result checks and occupied/capacity memory queries are outside that region.

Every actor loads only the Ed25519 plugin. `cases.json` is consumed by the shared
round-three runner, which records three fresh-canister trials and pinned artifacts.
The selected runtime uses the upstream serial32 backend, pinned in the plugin
manifest. This replaces serial64 field operations requiring emulated 128-bit
products on Wasm, without changing the verification contract.

The [reference-validation](reference-validation/) subdirectory independently
checks the portable OCaml semantics, including deliberately accepted mixed-order
points and rejected cofactor-only equations. Public interpreter/Wasm/Ash tests
use the same RFC/OpenSSL answers, not output generated by the plugin itself.

## Backend measurement

PocketIC, three fresh-canister trials per workload; all 42 trials passed for each
backend with identical outputs. The same compiler and fixture inputs were used.
Only the plugin manifest backend configuration changed.

| Public operation | Default64 instructions | Selected32 instructions | Reduction | Allocated bytes, either backend |
|---|---:|---:|---:|---:|
| derivePublicKey | 1,707,577 | 888,629 | 47.96% | 88 |
| keyPairFromSeed | 1,707,899 | 888,951 | 47.95% | 160 |
| validatePublicKey | 482,968 | 183,651 | 61.97% | 32 |
| sign, 32-byte message | 3,455,698 | 1,802,738 | 47.83% | 120 |
| verify, 32-byte message | 6,267,668 | 2,306,648 | 63.20% | 32 |
| sign, 1 KiB message | 3,562,223 | 1,909,263 | 46.40% | 120 |
| verify, 1 KiB message | 6,372,760 | 2,377,443 | 62.69% | 32 |

Compiled actor Wasm grew by 10,499 bytes. Allocation and all recorded occupied-heap
and Wasm-capacity snapshots were identical between backends. These are per-call
managed-allocation measurements, not a claim that the runtime stack consumes no
memory. The short trials did not trigger collection.
