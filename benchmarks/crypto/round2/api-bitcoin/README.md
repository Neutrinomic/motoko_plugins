# Bitcoin public API coverage

`inventory.json` maps every callable in the frozen `mo:fast/Bitcoin/{Hash,Address,Bip32,Script,Transaction}` modules to an isolated measured operation: 47 surfaces, including the `Hash.digest256` alias, the returned tagged-hash closure, and both prepared transaction hasher methods. Five transaction constants and public types are not callables.

`cases.json` contains 47 plugin-backed fixtures and 40 pure Motoko counterparts. `generate.py` regenerates all actors and metadata. `check.py` compiles each actor using the delivered frozen plugin artifacts; `check.json` records 87 successful compilations. These local compilation checks do not substitute for the parent benchmark runner's immutable three-trial stages and output checks.

Expected outputs come from Python hashlib/HMAC, independent affine secp256k1 arithmetic, an independently checked BIP340 signing equation, Base58 and BIP173/BIP350 encoders, BIP32 vector 2 plus independent public derivation, and independent Bitcoin transaction wire/sighash encodings. No expected output is read from either implementation under measurement. The generator imports only guarded oracle helpers from the existing curve and transaction generators, without running those generators.

Every operation is timed separately. Inputs and preparation are outside timing. Construction-only cases verify returned closures/nodes in the output query. Cold prepared-hasher method cases prepare the object outside timing but include its first lazy common-hash computation inside timing. Result encoding, node serialization for verification, and equality checks occur outside timing.

Pure Motoko counterparts use pinned `bitcoin@0.2.1` and `sha2@0.1.14` public APIs. Where the package exposes primitives rather than the exact helper, the actor includes a documented composition: point validation, network checking, tagged-hash closure, script construction/serialization, Taproot tweak and output encoding, or wtxid hashing. Script serializer output includes a CompactSize prefix; adapters remove that prefix inside timing to match raw-script output. The PUSHDATA1 fixture explicitly includes the required opcode. Taproot comparison uses key-path DEFAULT with equal spent scripts because the package's API accepts one shared script. No Taproot script-path comparison or double-prehashed signature comparison is introduced.

Seven rows lack a published equivalent: Taproot secret-key tweaking, BIP340 key-path signing, BIP143 one-shot hashing, and the constructors/methods of the reusable BIP143 and Taproot hashers. Each absence has a specific inventory note. The trivial `hrp` counterpart is an explicit pure Motoko adapter over the package's network type, not a claimed exported package helper.

Sixteen pure counterparts have distinct `-validated` case identities, listed in `validated-cases.json`. Their measured adapters add the native input constraints before invoking published package operations. BIP32 serialization and derivation check chain-code and fingerprint lengths, depth-zero metadata, compressed key length, canonical point encoding, depth bounds and strict text-path policy. Key constructors/fingerprints normalize canonical SEC1 bytes. Script helpers check data lengths, witness/leaf versions, choose minimal push encodings and remove the package serializer prefix inside measurement. TapLeaf uses the raw script as its input, composing public CompactSize and tagged-hash APIs; it does not substitute a pre-parsed script. Original unvalidated source files remain available for previously frozen historical stages, but the current inventory selects only corrected peers.

Transaction wtxid uses a transaction with empty witness stacks, explicitly labelled in its size column; witness encoding is not inferred from this row. Results benchmark successful inputs and do not claim equivalent error representations between the packages.
