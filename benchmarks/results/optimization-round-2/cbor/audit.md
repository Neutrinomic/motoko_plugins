Independent audit completed on 2026-10-11. The retained change is approved against plugins `0df5cd2d63d4b592e08c4c7a5f9d1e76fac22152`; no blocking finding remains.

The production change reuses the existing `Context.scalar` buffer when decoding arbitrary-size `Nat`/`Int`, and sets LEB continuation/sign bits in the existing conversion loop. It removes the separate transformation pass. There is no new representation, API, persistent storage, compiler change or ABI change. Fixed-width integers and encoding are unaffected.

- For each seven-bit group, XOR with `0x80` produces the previous positive continuation byte; XOR with `0xff` produces the previous complemented negative group plus its continuation bit. Trailing-zero removal and sign extension inspect the unmasked group, and the final continuation bit is cleared. The output is nonempty even for zero and the negative value −1, making the final `expect` valid for every admitted input.
- A parsed integer contains at most 4,096 magnitude bytes. The capacity expression therefore fits `usize`, including on Wasm, and bounds the output by `MAX_LEB_BYTES`. The scratch vector is replaced only when its capacity is insufficient. Input length, integer range, depth, item and byte checks remain input-dependent and stay in the runtime. Redundant leading-zero bytes are checked against the original input limit before trimming.
- Integer byte slices borrow the immutable input, never the scalar buffer. `cbor_read_bigint` clears the borrowed-string selector before exposing its new LEB data. The generator immediately feeds that data to `BigNum.of_leb128`; its temporary `ReadBuf` is synchronously consumed into an immediate integer or separately managed bigint before the next decoder can reuse the scratch buffer. The existing synchronous no-GC-safepoint contract remains unchanged. Managed values do not retain a pointer into the scalar vector.
- A terminal parse/range failure uses the original `vec![0]` fallback. An intermediate clear-and-push version added 79 instructions on the negative-to-`Nat` error; restoring the simpler original fallback removes that regression. No successful-input scratch branch was added for errors.
