# Independent JSON audit, round 2

The reviewed change has no unresolved correctness or safety findings. It keeps ABI 1, the JSON profile, limits, result types and GC contract unchanged. Final runtime source SHA-256: `fd2b16271238c9f0a01ec46d65ca94bde80439785517ca64c18e8432618c3bfb`; runtime Wasm: `f6c0ea9e7cb2d2249e17492711b2a34ebb5e88ae3d1c0d4f33eb63b1442a4a9e`.

The compiler substitutes OCaml `String.length` only for compiler-owned literal lengths. This counts bytes, matching the UTF-8 bytes emitted by `Text.lit` and `Text.to_blob`, rather than Unicode characters. Dynamic strings still obtain their runtime lengths. Literal creation, pointer lifetime and error-path borrowing are unchanged.

The integer encoder reuses the existing `decimal_word` routine instead of creating a formatting string for every base-1,000,000,000 chunk. Each remainder is between 0 and 999,999,999, so it produces one to nine digits and the zero-padding slice cannot underflow. The leading chunk is not padded; internal zero chunks, zero itself and the existing sign handling remain correct. The existing 2,048-byte LEB preflight bounds the reserved capacity arithmetic; the exact decimal-digit limit still runs afterward. The stack buffer is copied immediately into the output vector, and no reference to it escapes. Scratch remains confined to the synchronous plugin call; managed result construction and allocation barriers are untouched.

An independent Python generator produced **678 direct signed/unsigned LEB vectors** covering powers of two and ten, boundary neighbors, negative values, zero padding and seeded random integers through 4,096 decimal digits. All matched exact Python decimal strings in a separate Rust test build. This bypasses the plugin's decimal decoder, avoiding a mutually consistent roundtrip bug. The [generator](validation/audit-integer-boundaries.py) and [result](validation/audit-integer-boundaries.log) are archived. The owner's 20 Rust tests, 10 Motoko fixtures, 604 scalar cases, 161 binary/Unicode cases and 9,263 syntax-oracle cases also passed; reviewed logs include limits, exact escaped-key errors and retained results across GC.

Independently checked all **55 phase cohorts × three trials × two versions**, including actor, manifest, runner, Wasm and package hashes; all 19 baseline package source hashes match commit `0df5cd2`. The compiler revision and binary are identical across both sides. All successful output hashes match, counters are deterministic and measured reclamation is zero. All native-library counters are unchanged. The six known serde/serde-core large-text decoder stack overflows per version remain recorded.

Of the 37 plugin phase cohorts, 23 use fewer instructions and 14 are unchanged. Eight integer encoder cohorts allocate less; the rest are unchanged. No sampled instruction or allocation regression was found. The array of 128 signed 128-digit integers saves 40.75% of instructions and 46.84% of cumulative allocated bytes. The 4,096-digit scalar saves 3.07% of instructions; numeric decoding is unchanged. Fixed-record gains from literal lengths are small (under 1%). These are incremental results against the completed first round, not universal codec speedups.

Inputs and validation remain outside the measured interval in identical actors; the complete conversion and result retention remain inside. Allocation means cumulative requested heap bytes, including scratch, not peak or retained heap. The implementation adds no new abstraction, compatibility branch, dependency or runtime check. No additional production fix was needed during this audit.
