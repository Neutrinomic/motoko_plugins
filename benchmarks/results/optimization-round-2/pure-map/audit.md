Independent audit completed 2026-10-11. No blocking correctness or performance finding remains. Audited generator SHA-256: `6d399b18e980452c5583e5984b6f366785ee2e9bc0c53ca7b9775d8e3384a1d9`; Map.mo: `01107cd94c9c8a4879ddc5bdbc3460e2a43df314c19b9cbd2d99b8a459492015`.

The native search now keeps its current node and depth in local variables instead of recursive calls. Its only entry starts at depth zero, where the old guard was always true. Every descent still loads the chosen child, increments depth, and checks `depth < 128` before examining that child. A hit at depth 127 and null at depth 127 remain valid; any successor at depth 128 still traps, including null. The counter cannot wrap, and a cyclic or forged tree cannot make the traversal unbounded. Equality exits the loop with the original node reference. Comparator argument order, one invocation per visited node, and callback effects remain unchanged.

The node, key, and comparator remain ordinary managed Motoko values across callbacks, with no borrowed addresses. Existing tuple forwarding barriers remain in use; allocating or reentrant callbacks have separate native frames. Search introduces no allocation, and updates retain their existing structural sharing and write barriers. The existing synchronous callback/GC contract is unchanged.

The merge change only retains both source tuple references already read for comparison. Its private source array cannot be changed by the comparator; mutable objects reachable through entries retain the same identity. Equal comparisons still choose the left entry, preserving stable order, and subsequent duplicate compaction still selects the last original key object and value. No public type, ABI, node representation, ordering rule, or persistent-memory behavior changes.

Independently traced affected APIs:

- Native search: `get`, `getEntry`, `containsKey`, all scalar `get` wrappers, and the wrapper compositions `isDisjoint`/`isSubmap`.
- Stable merge: unsorted `fromArray`, `fromIter`, `addList`, and `mapKeys` inputs. Sorted construction bypasses the changed merge.
- `alter`, `update`, and `insertWith` use the separate, unchanged native update traversal. Predicate `find`, folds, rank/select, cursors, and tree set operations also do not call this search helper. Their existing full-table rows must not be assigned speculative lookup gains.
