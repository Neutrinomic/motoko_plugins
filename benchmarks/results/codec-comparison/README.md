Measured on pocket-ic-server 14.0.0 with compiler `be7aa9f9b51b1737221d335465b7acc9a8dce423`
and development plugin ABI 1. See [provenance.json](provenance.json) for the exact
compiler, plugin, source, library, and harness hashes; raw reports record the
actual PocketIC version. Three trials used a fresh canister per workload.
Successful instruction counts were identical across all trials.

## What is measured

All implementations use the same actor, compiler, typed input, and input bytes.
The common record is `{active : Bool; id : Text; name : Text; tag : Text}`;
its array contains 1,024 records with varying IDs and booleans. Text IDs keep
wire semantics consistent: the JSON plugin represents unbounded integers as
strings, while serde ordinarily emits JSON numbers. Large inputs are a 64 KiB
ASCII Text for JSON and a 64 KiB Blob for CBOR.

- The plugin calls `Prim.to_json`/`Prim.from_json<T>` or
  `Prim.to_cbor`/`Prim.from_cbor<T>` and unwraps the successful Result.
- serde calls include `to_candid` before encoding and `from_candid` after
  decoding, as needed to obtain the same typed Motoko value.
- Standalone libraries include construction/extraction of their generic value
  trees. Required `[Nat8]`/Blob conversions are also inside the timed interval.

Input construction and encoded input preparation happen before timing. Each
phase clears prior output and runs four forced GC increments. The measured
interval includes successful Result unwrapping and retention of the result.
Reply serialization, independent validation, and message-end GC are excluded.
Synchronous GC would be included; none occurred in successful measured phases.
Allocation counts in [summary.csv](summary.csv) are cumulative heap allocation,
including temporary objects, not retained memory or RSS. Native output Text
may be a rope; JSON UTF-8 reply conversion happens outside timing for everyone.

Encoder output is checked semantically with host `JSON.parse` or independent
Python `cbor2 6.1.5`; key order and whitespace may differ. serde adds CBOR's
self-described tag, which the oracle accepts. Decoder inputs are generated by
Python, independently of every measured encoder. A separate query checks the
entire decoded typed value. Large decoded Text is flattened for that check to
avoid recursive comparison on a deep native-library rope; flattening is outside
timing. Decoder `output_bytes = 2` describes the `"ok"` validation reply, not the
returned object's heap size.

These results compare complete algorithms, representations, and generated
code. They do not isolate boundary overhead, prove a bound for arbitrary data,
or measure an optimized Wasm component implementation.

## Recorded failures and correctness findings

Both serde JSON decoders trap with stack overflow on the 64 KiB Text, in all
three trials. Their cells contain no instruction count or speedup. The raw
JSON run intentionally exits unsuccessfully with six failed measurements.
[expected-failures.json](expected-failures.json) records those exact workload/
implementation pairs; the summary validator rejects additional failures,
missing trials, or a changed failure reason. All other measured outputs passed
the independent checks.

An earlier correctness pilot also found `serde 3.5.0` emitted a literal newline
inside a JSON string for the name `Ada ☃ "hello"\n` (the final character was an
actual newline). Host JSON parsing rejected the output. The
[failed pilot](correctness-findings/serde-newline.json) is retained. The shared
performance record uses the same text without the newline so all encoder
results in the table are valid. This is not a comprehensive library audit.

## Current CandidX and SHA-256 checks

The same compiler and ABI 1 packages were also measured against the CandidX
Motoko library at `94c2868988d98e8f660a9aa569a0ebc36fcda8ea` and Mops
`sha2 0.2.5`. CandidX includes ordinary `to_candid` plus canonicalization;
SHA includes digest initialization and finalization.

| Workload | Native instructions | Plugin instructions | Native/plugin |
| --- | ---: | ---: | ---: |
| SHA-256, 32 bytes | 27,968 | 4,966 | 5.63× |
| SHA-256, 64 KiB | 20,253,300 | 4,888,128 | 4.14× |
| SHA-256, 1 MiB | 323,721,060 | 78,124,848 | 4.14× |
| CandidX, fixed record | 404,924 | 1,797 | 225.33× |
| CandidX, 64 KiB Blob | 210,032 | 66,508 | 3.16× |
| CandidX, 1,024 sparse records | 88,379,476 | 6,154,646 | 14.36× |

All three trials returned the oracle bytes, with no synchronous reclamation.
The control interval was 256 instructions; it is not subtracted. The
[full report](candidx-sha/results.json) also includes ordinary Candid and
canonicalization-only context phases.

## Reproduction and validation

Use the [benchmark guide](../../README.md#json-and-cbor-library-comparisons).
Sources and manifests are saved beside each raw report in `json/`, `cbor/`,
and `candidx-sha/`. Frozen harness/generator files preserve the measured
implementation; Wasm binaries are identified by hash rather than committed.
Run the frozen runner with explicit `--sdk-package` and `--canonicalizer`
paths if relocating it; reproduce through the repository harness as shown in
the guide.

The plugin changes passed 61 native Rust tests, 38 Motoko fixtures spanning
source/IR/lowered interpretation and compiled Wasm, and package-loading
checks. GC fixtures retain managed results and exercise abandoned partial
arrays. The [independent JSON audit](../../../plugins/json/tests/audit/README.md)
and [JSON optimization report](../json-optimized/README.md) contain additional
reproducible evidence. No compiler or SDK source was changed for these codecs.
