# CandidX fixed-shape specialization

The compiler now derives the visit count for records containing only supported
primitives and other records. Inside an array with a dynamic enclosing shape,
it derives the first element's shape once and charges the remaining visits in
one checked batch. Payload writing also reuses the existing static writer for
these subtrees, removing dynamic shape lookups and unused context arguments.
Options, variants, binary values and nested arrays still take their respective
value-dependent paths. ABI 1, `#ok`/`#err`, GC ownership and all limits remain.

This also fixes the interpreter's record-budget diagnostic: exhausting the
remaining visit budget reported `collection length limit`, whereas generated
Wasm correctly reported `value traversal limit`. Both now return the latter.

| Workload | Before instructions | After instructions | Reduction | Cumulative allocation, both |
|---|---:|---:|---:|---:|
| Optional array, 1,024 fixed records | 2,044,436 | 367,561 | 82.02% | 23,784 B |
| Optional array, 1,024 Text records | 1,613,331 | 515,407 | 68.05% | 23,640 B |
| Optional array, 1,024 mixed Nat8 records | 3,037,005 | 2,874,957 | 5.34% | 33,200 B |
| Sparse records, 1,024 | 6,154,646 | 6,140,310 | 0.23% | 22,624 B |
| Nested optional arrays | 411,895 | 409,207 | 0.65% | 3,328 B |
| Repeated variants, 6,000 / 64 tags | 10,756,821 | 10,756,821 | 0% | 276,776 B |
| Blob, 64 KiB | 66,508 | 66,508 | 0% | 65,608 B |

All 56 workload entries ran three trials with the same actor source and input
for baseline and candidate. Every phase had identical metrics across its three
trials, zero synchronous reclamation and matching output sizes/hashes. There
were 34 faster entries, 22 unchanged entries and no instruction regressions.
Cumulative allocated bytes were unchanged in
every case: this change improves traversal work, not scratch memory use.
Empty/singleton optional fixed-record arrays improve 1.1%/1.4%; corresponding
Text-record cases improve 1.9%/2.1%. Binary-record cases deliberately retain
input-dependent shape traversal. Ordinary Candid remains a correctness source
and contextual measurement, rather than an equivalent canonical encoder.

The four actor binaries shrink by 333, 32, 333 and 784 bytes for the main,
static, repeated and nested suites respectively. The specialized traversal adds
one bounded compiler analysis; it introduces no runtime API, context cache,
persistent allocation or dependency. The first element performs the existing
depth checks before the remaining visits are charged. Both multiplicands are
bounded by 2,000,000, so the emitted 64-bit product cannot overflow.

## Commands

The compiler is frozen at `f1ccbba5e445df9db03bbc35be557187ade9b436` and
was never rebuilt or edited. All build, compile, PocketIC and test commands ran
inside its `nix develop` shell, entered from that compiler checkout. Set:

```sh
export MOTOKO_ROOT=/srv/shared/code/motoko_experiments/motoko_sha
export CANDIDX_WORKTREE=/srv/shared/code/motoko_experiments/optimization-round/candidx
cd "$CANDIDX_WORKTREE"
mkdir -p _build/opt-candidx/baseline
cp -a dist/candidx _build/opt-candidx/baseline/candidx
python3 benchmarks/generate.py --out _build/opt-candidx/main
python3 benchmarks/generate-static-arrays.py --out _build/opt-candidx/static
python3 benchmarks/generate.py --repeated-variants --out _build/opt-candidx/repeated
python3 benchmarks/generate-candidx-nested-arrays.py --out _build/opt-candidx/nested
```

The package copy and all baseline actor builds preceded the source changes.
For a fresh reproduction, obtain the baseline CandidX package by building only
`candidx` at plugins revision `093957a` with the same frozen compiler. Compile
and measure baseline with the following loop, then apply the accepted source
changes and run the candidate build and same loop with `label=candidate` and
`package=dist/candidx`:

```sh
label=baseline
package=_build/opt-candidx/baseline/candidx
for suite in main static repeated nested; do
  directory=_build/opt-candidx/$suite
  "$MOTOKO_ROOT/bin/moc" --plugin "$package" --plugin dist/sha256 \
    "$directory/main.mo" -o "$directory/$label.wasm"
  node benchmarks/run.mjs --wasm "$directory/$label.wasm" \
    --cases "$directory/cases.json" --out "$directory/$label.json" \
    --label "$label" --trials 3 --filter 'control|candid' \
    --sdk-package /srv/shared/code/candidx/ts/package.json \
    --canonicalizer /srv/shared/code/candidx/ts/dist/index.js
done
scripts/build.sh --motoko "$MOTOKO_ROOT" --skip-motoko-build candidx
```

The main/repeated actor source also declares SHA methods, so its compile uses
the unchanged baseline `dist/sha256` package; the filter measures only CandidX
and control cases. Nested workloads reuse the existing fixed-array inputs
inside an option, with ordinary Candid plus the independent TypeScript
canonicalizer providing the exact-byte oracle. Measurements include successful
Result unwrapping and retain the output. Input setup, four forced GC increments,
output queries and oracle comparisons occur outside the measured interval.
Allocation is `rts_total_allocation`, not retained heap or process memory.
